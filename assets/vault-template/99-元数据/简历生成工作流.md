# 简历生成工作流（Agent 操作手册）

> 当用户发送一份招聘需求（JD）并要求生成简历时，agent 按此流程操作。
> 核心原则：**JD 是指挥棒，Vault 是素材库，内容不足就追问，追问结果同时写入 Vault。**

## 整体流程

```
用户发 JD
  → 1. 解析 JD（提取关键词和要求）
  → 2. 遍历 Vault（匹配相关经历/技能/项目）
  → 3. 内容充足性检查（关键步骤！）
  →     ├─ 充足 → 直接进入第5步
  →     └─ 不足 → 4. 追问补充子流程（追问→写入Vault→循环检查）
  → 5. 内容裁剪与重写（STAR + 数字 + JD对齐）
  → 6. 生成 HTML 简历（调用 resume-master 规范）
  → 7. 导出 PDF + 验证
  → 8. 交付 + 说明匹配策略和素材缺口
```

---

## 第一步：解析 JD

### 1.1 提取核心信息

从 JD 中提取以下内容，整理成结构化清单：

- **岗位名称**：如"高级产品经理"
- **公司/行业**：如"某互联网公司 / 电商"
- **岗位职责**：列出 3-5 条核心职责
- **任职要求**：
  - 硬性要求（学历、年限、必备技能）
  - 加分项（优先考虑的技能/经验）
- **关键词**：提取 10-20 个核心关键词（技能、工具、领域、能力）
- **隐含需求**：JD 没明说但能推断出的需求（如"抗压能力强"= 加班多/节奏快）

### 1.2 关键词分级

- **P0 必须匹配**：JD 明确要求的核心技能/经验，简历中必须出现
- **P1 尽量匹配**：加分项或重要技能，有就突出，没有就用相近经验替代
- **P2 锦上添花**：次要关键词，有空间就提

---

## 第二步：遍历 Vault 匹配素材

### 2.1 读取策略

按以下顺序读取 Vault 文件：

1. `00-人物画像/个人信息.md` → 简历头部信息
2. `00-人物画像/核心画像.md` → 个人简介、求职意向
3. `00-人物画像/职业定位.md` → 职业方向、竞争力标签
4. `01-经历时间线/` 下所有经历文件 → 核心素材
5. `03-项目作品/` 下所有项目文件 + `成果记录.md` → 补充素材
6. `02-技能矩阵/` 三个文件 → 技能模块
7. `04-教育背景/教育经历.md` → 教育模块
8. `05-证书奖项/证书奖项.md` → 证书模块
9. `06-自我认知/优势特长.md` → 个人优势模块

### 2.2 匹配方法

对每条经历/项目，计算与 JD 的匹配度：

- **高匹配**：经历中直接用到了 P0 关键词，且有数字结果 → 详细展开，放前面
- **中匹配**：经历与 JD 领域相关，或用到了 P1 关键词 → 精简描述，放后面
- **低匹配**：经历与 JD 关联不大 → 一句话带过，或直接不写
- **不匹配**：完全无关 → 不写入简历

### 2.3 技能匹配

- 从 `专业技能.md` 和 `工具栈.md` 中筛选出 JD 要求的技能
- 按"JD 要求的优先，熟练度高的优先"排序
- 简历技能模块只写 8-15 个，不要堆砌

---

## 第三步：内容充足性检查（关键步骤！）

生成简历前，必须先检查 Vault 素材是否足够支撑一份有竞争力的简历。**不要跳过这一步直接生成。**

### 3.1 检查清单

逐项检查，任何一项不达标都算"内容不足"：

- [ ] **P0 关键词覆盖**：JD 的 P0 关键词是否都有对应的经历/技能支撑？
- [ ] **经历数量**：是否有至少 2-3 段与 JD 相关的经历可以写入简历？
- [ ] **数字结果**：每段要写入简历的经历是否都有具体数字结果？
- [ ] **个人简介素材**：是否能从 Vault 中提炼出 3-4 条与 JD 对齐的个人亮点？
- [ ] **技能覆盖**：技能模块是否能覆盖 JD 要求的 80% 以上？
- [ ] **性格/软技能**：JD 强调的软技能（如沟通、领导力）是否有具体事例支撑？

### 3.2 判断结果

**全部达标 → 内容充足**：直接进入第五步（内容裁剪与重写）。

**任何一项不达标 → 内容不足**：进入第四步（追问补充子流程）。**不要先生成一版空洞的简历。**

---

## 第四步：追问补充子流程（核心闭环）

当 Vault 素材不足时，**不要编造，不要将就**，按以下流程追问用户。追问得到的新信息**必须同时写入 Vault**。

### 4.1 明确告诉用户缺什么

用清晰、具体的语言告诉用户当前素材的缺口，例如：

- "JD 要求有 **用户增长** 经验，但你的 Vault 里没有相关记录。你有没有做过拉新、留存、促活相关的事？"
- "你在 **XX 公司** 的经历缺少具体数字结果。那段时间你做的事最终效果怎么样？有数据吗？"
- "与这个岗位最相关的经历只有 **1 段**，可能不够有竞争力。还有没有其他项目或经历能体现你在这方面的能力？"

### 4.2 针对性追问（每次最多 3 个问题）

- 问题要具体，附选项或示例，让用户做"识别题"而非"问答题"
- 聚焦在能直接提升这份简历竞争力的信息上
- 不要问泛泛的"你还有什么经历"，要问具体的缺口

**追问示例**：

| 缺口类型 | 追问方式 |
|----------|----------|
| 缺某类经历 | "JD 要求有 XX 经验，你有没有做过类似的事？哪怕不是正式项目、哪怕只是帮朋友做的也算。" |
| 缺数字结果 | "你在 XX 项目里，最终结果怎么样？有具体数字吗？比如用户量、效率提升了多少、成本降低了多少、覆盖了多少人。" |
| 缺相关经历数量 | "这个岗位需要 XX 能力，你觉得自己哪几段经历最能体现这一点？能详细说说其中一段吗？" |
| 缺软技能事例 | "JD 强调跨团队协作，你有没有协调过多个部门或团队的经历？当时是什么情况？" |
| 缺项目细节 | "你提到做过 XX 项目，能具体说说你在里面做了什么吗？用了什么工具/方法？最后结果怎么样？" |

### 4.3 用户回答后立即写入 Vault

用户每回答一个问题，立即将信息结构化写入对应文件：

| 用户回答的内容 | 写入位置 |
|---------------|----------|
| 新的工作/实习/校园经历 | 复制 `01-经历时间线/_经历模板.md` 创建新文件 |
| 新的项目/作品/vibe coding 成果 | 复制 `03-项目作品/_项目模板.md`，或追加到 `成果记录.md` |
| 已有经历的补充细节/数字 | 更新对应经历文件 |
| 新的技能/工具 | 更新 `02-技能矩阵/` 下对应文件 |
| 性格特质/优势 | 更新 `06-自我认知/` 下对应文件 |
| 教育/证书信息 | 更新对应文件 |

**同时必须更新**：
- `99-元数据/画像更新日志.md`：追加一条更新记录
- `99-元数据/待补充清单.md`：已补充的项标记完成，新发现的缺口追加进去

### 4.4 循环检查

追问后，回到第三步重新评估内容是否充足：

- **充足了** → 进入第五步生成简历
- **还不够** → 继续追问，但**不要超过 3 轮**（避免用户疲劳）
- **用户说"没有了"或"记不清了"** → 接受现状，用现有素材生成简历，在第八步交付说明中标注哪些地方素材不足

### 4.5 闭环价值

这个追问子流程的核心价值是：**每生成一次简历，你的 Vault 就更完整一点。** 这次追问得到的经历，下次生成其他岗位的简历时自动可用，不需要重复回答。

## 第五步：内容裁剪与重写

### 5.1 经历重写原则（STAR + JD 对齐）

每条经历按以下结构重写：

```
【公司名】| 【岗位】| 【时间】
岗位概述：1 句话说清你在这个岗位的核心职责（与 JD 相关的部分）

• 【成就1一句话标题】：背景 + 你做了什么（突出 P0 关键词）+ 结果（数字）
• 【成就2一句话标题】：背景 + 你做了什么 + 结果（数字）
• 【成就3一句话标题】：（如果空间够）
```

### 5.2 关键词植入技巧

- **自然植入**：把 P0 关键词自然地融入经历描述，不要生硬堆砌
- **加粗突出**：核心技能、关键成果用加粗（resume-master 规范）
- **同义词覆盖**：如果 JD 用"用户增长"，你的经历写"用户增长"，不要只写"拉新"
- **标题前置**：成就标题里就包含关键词，HR 扫一眼就能看到

### 5.3 数字强化

- 每条经历至少有 1 个数字
- 数字要具体："提升 25%"比"大幅提升"好
- 如果 Vault 中没有数字，标注"待补充"并询问用户，不要编造

### 5.4 篇幅控制

- 简历控制在 1 页（resume-master 规范）
- 工作 5 年以内：1 页
- 工作 5-10 年：1-2 页（优先 1 页）
- 每段经历写 2-4 条成就，不要超过 4 条
- 最近的经历详细写，久远的经历精简写

---

## 第六步：生成 HTML 简历

### 6.1 调用 resume-master 规范

严格遵循 resume-master skill 的规范：

- **模板选择**：根据岗位类型选择模板
  - 技术岗 → 极客风尚 / 极简纯白
  - 产品/运营/市场 → 典雅酒红 / 清新蓝灰
  - 设计/创意 → 沉稳双栏 / 极简纯白
  - 如果用户有偏好，按用户选择
- **STAR 原则**：每条经历用 STAR 结构
- **加粗规则**：只加粗核心技能、关键成果，不加粗整句
- **样式规范**：font-size 13.5-16px，line-height 1.5 以下，4-6 个模块
- **一页原则**：尽量控制在 1 页

### 6.2 简历模块顺序

根据 JD 和用户情况决定模块顺序：

**通用顺序（社招）：**
1. 个人信息（姓名、联系方式、求职意向）
2. 个人优势 / 职业简介（3-4 条核心亮点，与 JD 对齐）
3. 工作经历（倒序，最近的在前）
4. 项目经历（如果有与 JD 高度相关的项目）
5. 技能特长
6. 教育背景
7. 证书奖项（可选）

**应届生顺序：**
1. 个人信息
2. 教育背景（放在前面）
3. 实习经历
4. 项目经历
5. 技能特长
6. 校园经历 / 证书奖项

### 6.3 个人简介写法

简历开头的 3-4 条个人简介，必须为 JD 量身定制：

```
• 【X年XX经验】：X年【行业】【岗位】经验，专注于【JD核心领域】
• 【核心能力1】：精通【P0技能1】，曾【具体成就，有数字】
• 【核心能力2】：擅长【P0技能2】，主导过【具体项目】，实现【数字结果】
• 【差异化优势】：【与其他候选人不同的地方，如跨领域经验/特定行业背景】
```

## 第七步：导出 PDF + 验证

### 7.1 导出 PDF

使用 resume-master 的脚本：
```
python {resume_master_path}/scripts/render_pdf.py --in <resume.html> --out <姓名_岗位_公司.pdf> --paper A4
```

如果脚本不可用，提示用户用浏览器打开 HTML，按 Ctrl+P 打印为 PDF。

### 7.2 验证清单

生成后逐项检查：

- [ ] **页数**：是否 1 页？（或符合预期）
- [ ] **关键词覆盖**：P0 关键词是否都出现在简历中？
- [ ] **数字**：每条经历是否都有数字？
- [ ] **加粗**：加粗是否合理？没有整句加粗？
- [ ] **信息准确**：姓名、联系方式、时间是否正确？
- [ ] **排版**：是否有溢出、重叠、空白过多？
- [ ] **JD 对齐**：HR 扫 10 秒能否看到与岗位匹配的核心信息？

### 7.3 预览验证

将 PDF 按页拆成图片，逐页检查视觉效果（使用 resume-master 的 `pdf_to_images.py` 脚本）。

---

## 第八步：交付 + 说明

### 8.1 交付内容

- **HTML 源文件**（可编辑，后续微调）
- **PDF 文件**（可直接投递到招聘软件/网站）

### 8.2 匹配策略说明

告诉用户这份简历是如何为 JD 定制的：

```
这份简历针对【岗位名称】做了以下定制：
1. 突出了【P0技能1】和【P0技能2】，在个人简介和工作经历中重点展示
2. 将【某段经历】放在最前面，因为它与 JD 的【某要求】高度匹配
3. 弱化了【某段不相关经历】，只保留一句话
4. 技能模块只保留了与 JD 相关的 X 个技能
5. 个人简介围绕 JD 的核心要求重新撰写
```

### 8.3 素材缺口说明（如果有）

如果在第三步检查中发现了缺口，且用户说"没有了"，必须在交付时明确标注：

```
需要注意（素材缺口）：
- JD 要求的【某技能/经验】你没有直接经验，我用了【相近经验】替代，面试时需要准备说法
- 【某段经历】缺少具体数字，建议补充后会更有说服力
- 这些缺口已经记录在 Vault 的「待补充清单」中，后续想到了可以随时补充
```

### 8.4 后续建议

- 建议用户通读一遍，确认信息准确
- 提醒用户 PDF 可以直接上传到招聘软件/网站的简历投递处
- 询问是否需要调整模板样式或内容侧重点
- 提醒用户：这次追问补充的内容已经写入 Vault，下次生成其他岗位简历时自动可用

## 特殊情况处理

### JD 信息不足

- 如果用户只给了岗位名称，没有详细 JD
- 先搜索该岗位的通用 JD，提取常见要求
- 生成一份"通用版"简历，并告诉用户这是通用版，有具体 JD 可以再定制

### Vault 完全空白（第一次使用就生成简历）

- 不要直接生成（素材为零）
- 告诉用户需要先蒸馏一些基础信息
- 立即进入画像蒸馏模式，从最基础的信息开始问
- 凑够"姓名 + 联系方式 + 一段完整经历"后，可以先生成一版极简简历
- 同时继续追问补充

### 用户要求多版本

- 如果用户要同时投多个岗位
- 每个岗位生成独立的 HTML/PDF，命名区分（如 `张三_产品经理_电商.html`）
- 可以先生成一个通用版，再基于通用版定制各岗位版本
- 每个版本的追问补充都写入 Vault，共享素材库
